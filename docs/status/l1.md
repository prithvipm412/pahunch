# L1 · Claude Code status

## Done

- Replaced the fake solver with a real Modified Nodal Analysis (MNA) solver in `src/physics`.
  - Wires and closed switches merge grid points via union-find; open switches are removed.
  - Batteries are stamped as their Norton equivalent (default 3 V, fixed 0.5 Ω internal
    resistance) so no extra branch-current unknowns are needed; bulbs/resistors default to 10 Ω.
  - Current through zero-resistance wires/closed switches (not directly observable from node
    voltages) is recovered via a per-island spanning-tree subtree-sum of the surrounding
    resistor/bulb/battery currents; redundant/parallel wire edges report 0 (indeterminate split).
  - Bulb state uses `ratio = power / (3^2 / R_bulb)` with thresholds: off < 5%, dim < 50%,
    normal < 150%, bright < 300%, overload ≥ 300%.
  - `src/physics/validate.ts` detects `empty`, `no_battery`, `short_circuit` (direct wire-merge of
    battery terminals, or post-solve battery current > 2 A), `open_circuit` (battery has no closed
    loop excluding its own edge), and `floating:<id>` warnings for components not connected to a
    battery-containing island.
  - `solve()` never throws — singular-matrix / unexpected-error paths fall back to an `ok:false`
    result with every component reported off.
- Added 10 fixtures under `src/contracts/fixtures/` covering single bulb, series/parallel bulbs,
  open/closed switch, bulb+resistor, short circuit, broken wire, mixed series-parallel, and two
  batteries in series — exercised by `src/physics/solve.test.ts` along with series-vs-parallel
  current comparison and a 200-trial randomized-netlist fuzz test.
- `solve()`'s signature is unchanged.

## Phase 2 — Sparsh mode (audio + touch circuit builder)

- Added `src/physics/describe.ts`: `describeCircuit(netlist)` returns `{ counts, topology }`
  — a purely structural (no `solve()` call) read of a netlist, used for Sparsh's long-press
  summary. `topology` is `'empty'` (no components), `'incomplete'` (no battery, or battery not
  in a closed loop, or a closed loop with no load components — reuses `validate()`'s
  `no_battery`/`open_circuit` errors), `'series'` (loads form a single chain, no duplicate
  node-pair and no node touched by 3+ loads), `'parallel'` (all loads share one node pair), or
  `'mixed'` (anything else, e.g. a series run feeding a parallel pair). Covered by
  `src/physics/describe.test.ts`, reusing the existing `src/contracts/fixtures/*.json` plus a
  few hand-built edge cases.
- Built Sparsh as a pure state machine (`src/sparsh/machine.ts`: `sparshReducer(state, event) ->
  { state, effects }`) plus a thin React screen (`src/sparsh/index.tsx`) that only translates
  touch gestures into machine events and executes the returned effects (speak/vibrate/solve/
  sonify/navigate). 55 vitest tests across `machine.test.ts`, `describe.test.ts`, and
  `gestures.test.ts` (pure swipe-direction and touch→grid-point math in `src/sparsh/gestures.ts`)
  cover every gesture path: cursor movement + edges, the part-placement menu, remove/toggle on
  existing parts, long-press summaries for every topology, all `solve()` outcomes on two-finger
  tap, and Explore mode's drag/pulse/rest/exit flow.
- Design decisions not fully spelled out in the task, so documented here: the edit menu for an
  existing part (opened by double-tapping it) has a single action for non-switch parts (remove)
  and two for a switch (remove, toggle), cycled with left/right swipes like the part-placement
  menu; the "toggle" option previews the *resulting* state using the existing `switch_open`/
  `switch_closed` clips (no new clip names were introduced — see Phase-2 task rule 4). A `mixed`
  topology speaks both `in_series` and `in_parallel` in the long-press summary, since no separate
  "mixed" clip exists. One-finger drag in Explore mode is resolved to the nearest grid dot (same
  model as Build-mode cursor movement), not to a continuous position along a component's line.
- Audio: every `playClip` call goes through `src/sparsh/clips.ts`'s `fallbackFor()`, which is
  always the English text per the task spec (independent of the UI's selected language, which
  still picks the clip-file folder). The screen does **not** use `playSequence` from `src/audio`
  because it doesn't accept a fallback per clip — it awaits `playClip(lang, name, fallbackFor(name))`
  in sequence itself instead.
- `npm run typecheck && npm test && npm run build` all pass (55/55 tests). Manually verified in
  Chrome that the unlock overlay, 5×5 grid, cursor, and caption render correctly with no console
  errors; the available browser automation only simulates mouse events, not real touch gestures,
  so the swipe/double-tap/long-press/two-finger flows were verified via the unit tests above
  rather than live in a browser — flagging this so a real device/touch-emulation pass is still
  worth doing before this ships.
