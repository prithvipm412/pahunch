### Phase 6 — Robustness & Resiliency for Live Deployments

**Files created / changed:**

| File | Purpose |
|---|---|
| `api/scan.ts` | Defensively strips `data:...;base64,` prefixes, validates mimeType (jpeg/png/webp), enforces 4MB max payload (413), retries on 400 schema error without `responseSchema`, retries on 429/5xx after 1.5s delay, normalizes multi-dot straight spans (splits long wires, places components on segment 0 and fills rest with wire segments), validates Netlist shape (422 `unreadable`), sanitizes server error logs |
| `src/draw/imageUtils.ts` | Always exports JPEG via canvas at ~0.7 quality and longest side ≤1024px, strips `data:...;base64,` prefix for pure base64 export, supports `skipBlur` option for sample drawings |
| `src/draw/scanApi.ts` | Passes `{ image, mimeType, hint }` with clean prefix-stripped base64, maps 422 unreadable to friendly student copy |
| `src/draw/index.tsx` | Routes bundled sample PNGs through canvas JPEG pre-processing with `skipBlur: true` |
| `src/draw/draw.test.ts` | 37 unit tests covering prefix stripping, mimeType normalization/validation, >4MB payload rejection, multi-dot straight wire splitting, multi-dot component extension splitting, diagonal/out-of-range rejection, safe markdown fence JSON extraction, and handler HTTP status flows |

**What works:**
- **Client base64 & MIME cleanliness**: Client sends pure base64 with no data URL prefixes and explicit `mimeType: "image/jpeg"`. All images, including bundled PNG samples, are drawn to canvas and exported as ~0.7 quality JPEG with longest side ≤1024px.
- **Server defensive parsing**: `api/scan.ts` strips any data URL prefixes, validates MIME types (`image/jpeg`, `image/png`, `image/webp`), and rejects payloads >4MB with HTTP 413.
- **Multi-dot straight component normalization & splitting**:
  - Long straight wires spanning multiple grid dots (horizontal or vertical) are automatically partitioned into unit wire segments between adjacent dots with unique IDs.
  - Long straight components (`battery`, `bulb`, `resistor`, `switch`) are placed on the first unit segment, and the remainder of the span is filled with unit wire segments with unique IDs.
  - Only diagonal parts, zero-length parts, or out-of-range coordinates are rejected.
- **Gemini retry & fallback mechanisms**:
  - If Gemini returns 400 mentioning `responseSchema` / `response_mime_type` / `unsupported`, retries once without `responseSchema` asking for JSON in the prompt, safely extracting JSON by stripping markdown code fences or surrounding prose.
  - If Gemini returns 429 or 5xx, waits 1.5s and retries once.
- **Strict Netlist shape validation (HTTP 422)**:
  - Validates every component: known type (`battery`, `bulb`, `resistor`, `switch`, `wire`), integer row/col within `0..4`.
  - Malformed or incomplete JSON yields HTTP 422 `{ error: 'unreadable' }` without server crashes.
- **Server error logging**: Logs error details server-side via `console.error` with the API key redacted and image payload omitted so errors appear clearly in Vercel runtime logs while students see friendly localized messages.

## Running the API locally

```bash
# 1. Install Vercel CLI globally (or use npx)
npm i -g vercel

# 2. Create a local env file — NEVER commit this
echo 'GEMINI_API_KEY=your_key_here' >> .env.local
# Optionally override the model:
echo 'GEMINI_MODEL=gemini-3.8-flash' >> .env.local

# 3. Start the dev server (runs both Vite frontend and Vercel API routes)
npx vercel dev
# → http://localhost:3000

# Without a key the app still works — /api/scan returns a demo netlist
# with the X-Demo: 1 header, confidence: 1.0, and a banner in the UI.
```

> **Never commit `.env.local`** — it is in `.gitignore` by default from Vercel templates.
> The `GEMINI_API_KEY` is read **only** inside `api/scan.ts` on the server; it is never sent to the client.

## Interface changes

- **`api/scan.ts`**:
  - Request body accepts `{ image: string, mimeType?: string, hint?: string }`.
  - Rejects payloads > 4MB with HTTP 413.
  - Rejects unsupported MIME types with HTTP 400.
  - Normalizes straight multi-dot spans into unit segments (wires split into unit wires; battery/bulb/resistor/switch placed on first unit segment and filled with wires).
  - Returns HTTP 422 `{ error: 'unreadable' }` if Gemini response does not strictly conform to the 5x5 Netlist structure or contains diagonal/out-of-range parts.
- **`src/draw/scanApi.ts`**: `scanCircuit(base64, hint?, mimeType?)` strips prefixes and defaults `mimeType` to `'image/jpeg'`.
- **`src/draw/imageUtils.ts`**: `processImage(file, options?)` accepts `Blob | File` and `options?: { skipBlur?: boolean }`. Output `base64` is guaranteed to be stripped of `data:...;base64,` prefixes.
